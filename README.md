# TaskHub - 研发任务追踪系统

一个面向中小研发团队的任务追踪与反馈收集系统。采用"任务池 + 抢单制"模式，让任务在团队内部自发流动；同时内置员工反馈与人工审核机制，持续驱动产品迭代。

---

## 核心功能

### 1. 任务追踪（Task Management）
- **任务池**：支持跨部门创建任务，发布到公共任务池
- **抢单认领**：研发人员根据当前负载自主认领任务
- **状态流转**：草稿 → 待认领 → 进行中 → 待验收 → 已完成
- **权限控制**：创建者、认领者、管理员分别拥有不同操作权限
- **操作留痕**：每次状态变更自动记录日志，支持追溯

### 2. 反馈收集与审核（Feedback Loop）
- **员工提交**：试用过程中随时提交功能建议、Bug 反馈、体验优化
- **人工审核**：管理员对反馈进行二次审核（通过 / 驳回 / 已实现）
- **迭代方向**：审核通过的反馈自动沉淀为下一轮迭代方向
- **权限隔离**：普通员工只能看到自己的反馈和已公开的反馈，管理员可查看全部

## 快速开始

### 1. 克隆仓库

```bash
git clone https://github.com/meikis/taskhub.git
cd taskhub/backend
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

> 若 Alpine/musl 环境遇到 `bcrypt` 版本兼容问题，系统已自动降级为原生 `bcrypt` 库实现。

### 3. 初始化数据

```bash
python init_data.py
```

此命令会创建 SQLite 数据库并初始化默认账号：

| 账号 | 密码 | 角色 |
|------|------|------|
| admin | admin123 | 管理员 |
| zhangsan | 123456 | 员工 |
| lisi | 123456 | 员工 |
| wangwu | 123456 | 员工 |

### 4. 启动服务

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 5. 访问系统

打开浏览器访问：http://localhost:8000

API 文档：http://localhost:8000/docs

## 系统截图与使用流程

### 任务看板
首页展示任务状态看板，分为"待认领、进行中、待验收、已完成、已挂起"五列，直观呈现全局进度。

### 新建任务
点击"新建任务"，填写标题、描述、类型、优先级，任务即刻进入任务池。

### 任务认领与流转
- 员工在看板中点击任务，进入详情页
- 状态为"待认领"时，点击"认领任务"
- 处理过程中可随时更新状态：开始处理 → 提交验收 → 验收通过

### 提交反馈
进入"反馈建议"页面，选择类别（功能改进 / Bug反馈 / 体验优化 / 新功能 / 其他），填写标题和详细描述后提交。

### 反馈审核（管理员）
管理员进入"审核面板"，查看所有"待审核"反馈：
- **通过**：标记为 approved，可指定优先级，纳入迭代 backlog
- **驳回**：标记为 rejected，需填写审核意见
- **已实现**：如反馈内容已在其他迭代中完成，直接标记为 implemented

## 关键设计决策

1. **为什么用 SQLite？**
   - 项目面向中小型团队，单节点部署即可满足需求。
   - 后期如需多节点部署，只需把 `DATABASE_URL` 改为 PostgreSQL 连接串，无需修改任何业务代码。

2. **为什么前端用 CDN 而非构建工具？**
   - 减少依赖和构建步骤，iSH/Alpine 等受限环境下也能直接运行。
   - 后续如需工程化，可随时迁移到 Vite + Element Plus 的构建方案。

3. **反馈为什么必须人工审核？**
   - 不是所有员工反馈都需要实现，人工审核起到筛选、去重、优先级排序的作用。
   - 审核通过的反馈才进入迭代 backlog，避免需求膨胀。
